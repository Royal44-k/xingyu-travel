# 国内自由行旅游服务平台开发规格文档计划（v1.0）

## 1. 文档目标与交付物

- 产出内容一致的 `旅行服务平台_开发规格说明书_v1.0.docx` 与 `.md`，DOCX 用于正式评审，Markdown 用于代码仓库持续维护。
- 产品定位：面向 18–35 岁国内自由行用户，以“透明比价、可信搭子、攻略转行程、主动式应急 AI”为核心闭环。
- MVP 按 4–6 个月、约 8–10 人团队设计；采用比价后跳转合作方成交，不承担站内出票、支付、退款和清结算。
- 文档包含版本记录、术语表、产品需求、角色权限、业务流程、状态机、领域模型、API 契约、部署架构、安全合规、测试验收、运营后台、路线图和需求追踪矩阵。
- DOCX 采用 `compact_reference_guide` 样式和技术规格书式首页，使用真实标题层级、目录、编号与明确表格几何；完成后逐页渲染检查排版，Markdown 与 DOCX 校验章节和版本一致。

## 2. 产品与功能规格

- **统一比价**
  - 覆盖机票、酒店、景点门票；统一标准化税费、行李、餐食、退改、入住政策、预约时段和报价有效期。
  - 提供“真实总价”和价格解释，不将不同条件的报价简单按裸价排序。
  - 支持筛选、价格日历、收藏、降价提醒、同屏对比、供应商可信度、更新时间及 CPS 深链归因。
  - 没有正式供应商时使用模拟适配器和沙箱数据；生产环境禁止依赖网页抓取。

- **攻略广场**
  - 支持图文、最多九图、地点卡片、标签、行程节点和商品卡片，以及关注、评论、收藏、分享、举报。
  - 支持把攻略中的地点、天数和预算抽取成“待确认行程草稿”，再进入比价。
  - 提供个性化与非个性化双 feed、推荐关闭入口、兴趣标签查看和删除能力，以满足算法透明与用户选择要求。[算法推荐管理规定](https://www.cac.gov.cn/2022-01/04/c_1642894606364259.htm)
  - 发布流程包括敏感内容、广告、诈骗、联系方式、版权和 AI 生成内容检测；AI 生成或改写内容添加显式与元数据标识。[人工智能生成合成内容标识办法](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)

- **旅游搭子**
  - 游客可公开浏览；发布、匹配、私聊和线下结伴仅限 18 岁以上实名用户。
  - 实名采用身份二要素核验；人脸为可选增强徽章。平台仅保存核验状态、交易号和脱敏摘要，不保存证件照片或原始身份证号。
  - 硬性过滤包括目的地、日期重叠、成年状态、招募容量、认证要求、拉黑关系和安全风控状态。
  - 匹配评分固定为：日期契合 25%、预算 20%、旅行节奏 15%、兴趣 15%、路线方式 10%、住宿边界 5%、作息 5%、社交偏好 5%；向用户解释前三项匹配原因。
  - 双方同意后开启站内聊天；联系信息仅在双方主动确认后交换。提供举报、拉黑、可信联系人、行程分享、平安签到和失联提醒。
  - 不公开精确实时位置，不使用宗教、民族、健康等敏感属性进行推荐。

- **AI 旅行助手与行程守护**
  - 常规问答默认使用 Qwen3.7-Plus；复杂多约束规划和高风险应急升级至 Qwen3.7-Max；低风险分类、摘要使用 Flash。模型名称全部配置化，并在上线前重新评测。百炼官方将 Plus 定位为性能/成本平衡方案、Max 用于复杂多步骤任务，并提供 OpenAI 兼容接口。[百炼模型说明](https://help.aliyun.com/en/model-studio/what-is-model-studio)
  - 模型只负责意图识别、推理、排序和解释；航班、天气、景区状态、地图路线、报价与订单事实必须来自函数调用或正式 API。[函数调用说明](https://help.aliyun.com/en/model-studio/qwen-function-calling)
  - 用户授权“行程守护”后，后台监测航变、恶劣天气和景区关闭，输出带来源、时间、成本、耗时和风险的 Plan A/B/C，不自动改签或下单。
  - 覆盖航班取消/延误、极端天气、景区关闭、交通中断、证件遗失、轻度健康问题和人身安全事件；遇到紧急危险优先提示联系警方、急救、消防及官方机构。
  - 建立审核过的旅行安全知识库、工具调用审计、引用与数据新鲜度标识；禁止将模型输出包装成医疗诊断、法律结论或官方救援承诺。
  - 使用已备案模型并在产品中公示模型名称和备案信息。[生成式 AI 备案公告](https://www.cac.gov.cn/2024-04/02/c_1713729983803145.htm)

- **差异化能力与路线图**
  - MVP：真实总价、攻略转行程、可解释搭子匹配、同行决策室、主动行程守护。
  - P1：短视频、多人预算分摊、攻略自动生成草稿、会员版高级守护、更多供应商。
  - P2：出境游、多语言、站内交易、保险协同、AR 导览和开放商家平台。
  - 明确排除首版原生 App、微信小程序、短视频、国际目的地、站内支付、自动改签和未成年人互动。

## 3. 技术架构与接口

- **技术基线**
  - Node.js 24 LTS 最新安全补丁、Next.js 16.2、NestJS 11 + Fastify、TypeScript、pnpm workspace。
  - 模块化单体按身份、用户、内容、搜索比价、行程、匹配、聊天、AI、通知、风控、后台等领域隔离；独立 Worker 处理聚合搜索、审核、通知和行程监测。
  - RDS PostgreSQL 17 + PostGIS + pgvector；Tair Redis 7 用于缓存、限流、会话、WebSocket 广播和任务队列。阿里云 RDS 已支持 PostgreSQL 17 与 pgvector/PostGIS 扩展。[RDS 公告](https://help.aliyun.com/zh/rds/apsaradb-rds-for-postgresql/important-notice/)、[扩展列表](https://help.aliyun.com/en/rds/apsaradb-rds-for-postgresql/extensions-supported-by-apsaradb-rds-for-postgresql)

- **阿里云部署**
  - 华东地域单 VPC、双可用区；ALB 后部署至少两台无状态 ECS，数据库和缓存仅开放私网。
  - 使用 RDS 高可用版、Tair、OSS 私有桶、CDN、WAF、证书服务、KMS/凭据管理、SLS、ARMS、Prometheus、云备份和 RAM 最小权限。
  - 静态图片经前端直传 OSS，服务端签发短期凭证；CDN 仅访问处理后的公开资源。
  - MVP 可用性目标 99.9%，核心内部 API p95 ≤500ms；聚合搜索 2.5 秒内出现首批结果、8 秒硬超时；RPO ≤15 分钟、RTO ≤2 小时。
  - 中国内地部署上线前完成 ICP、公安联网备案及适用的许可证/备案评估。[阿里云备案流程](https://help.aliyun.com/zh/icp-filing/basic-icp-service/getting-started/quick-start-for-icp-filing-for-personal-websites)

- **公共接口与核心类型**
  - REST API 统一使用 `/api/v1`、OpenAPI 3.1、游标分页、幂等键、统一错误码和请求追踪 ID。
  - `POST /comparison/searches` 返回 `202 + search_id`，通过 SSE 推送增量报价；聊天和通知使用 `/ws/chat`、`/ws/notifications`。
  - 核心资源包括 `Post`、`Trip`、`ItineraryItem`、`PartnerIntent`、`MatchResult`、`NormalizedOffer`、`TripRiskEvent`、`AlternativePlan`、`ModerationCase`。
  - 统一适配器包括 `InventoryProvider`、`DeepLinkProvider`、`MapProvider`、`WeatherProvider`、`FlightStatusProvider`、`IdentityProvider`、`NotificationProvider`、`LLMProvider`。
  - AI 响应必须返回 `risk_level`、`answer`、`alternatives[]`、`evidence[]`、`data_freshness`、`requires_human_help`，高风险回答禁止只返回自然语言。
  - 领域事件通过 PostgreSQL transactional outbox 保证可靠性，包括 `QuoteUpdated`、`TripRiskDetected`、`MatchSuggested`、`ModerationFlagged`。

## 4. 安全、合规与运营设计

- 按个人信息保护最小必要原则建设：手机号、证件核验、行程、精确位置和健康描述分级存储、单独同意、可撤回、可导出、可删除；行踪和生物识别按敏感个人信息处理。[个人信息保护法](https://www.samr.gov.cn/wljys/gzzd/art/2023/art_3ef1e889c1e644d4b65b5f5c7f432386.html)
- 按等保二级目标设计网络、主机、应用、数据、审计和应急措施，正式定级由上线前合规评估确认。
- 在线旅游交易撮合、供应商展示、价格说明、投诉与应急处理按文旅部平台经营者要求设计。[在线旅游经营服务管理暂行规定](https://zwgk.mct.gov.cn/zfxxgkml/zcfg/bmgz/202012/t20201204_905349.html)
- 后台包含内容审核、用户处置、举报工单、供应商健康度、报价新鲜度、AI 提示词/模型配置、知识库审核、行程风险事件和特性开关。
- CPS、推荐、匹配、AI 和行程守护分别建立事件字典；首版记录指标口径和基线，不以未经市场验证的增长数字作为开发验收门槛。
- 合规章节作为工程清单，不替代律师、通信管理局或文旅主管部门的正式意见。

## 5. 测试与验收

- **功能验收**：三类产品报价标准化、供应商超时/重复/过期、深链归因、攻略转行程、匹配与互斥条件、双向聊天授权、举报处置、非个性化 feed。
- **应急 AI**：建立不少于 200 条评测集，覆盖常规规划、实时事实、航变/天气/景区事件和提示注入；验证引用、新鲜度、工具失败降级、禁止自动下单及紧急服务优先级。
- **安全测试**：OWASP ASVS L2、越权、验证码滥用、文件上传、XSS/CSRF/SSRF、敏感日志、聊天骚扰、联系方式泄漏、供应商回调伪造和 AI 工具注入。
- **性能与韧性**：模拟单供应商和多供应商故障、RDS/Tair 短暂不可用、Worker 重启、重复事件及多 ECS 切换；验证限流、熔断、幂等、重试和降级页。
- **端到端验收**：移动端完成“浏览攻略 → 转为行程 → 比价跳转 → 发布搭子 → 匹配聊天 → 开启守护 → 收到风险预警 → 选择替代方案”的完整链路。
- **发布流程**：开发、预发布、生产三环境；供应接口先沙箱后灰度；数据库向前兼容迁移；特性开关控制 AI、匹配和供应商；上线前完成备份恢复演练、合规检查与回滚演练。
- **文档验收**：DOCX 与 Markdown 章节、编号、接口和版本一致；DOCX 每页通过渲染检查，无表格截断、字体缺失、错页或占位内容。
