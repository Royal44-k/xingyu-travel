## 保留与去重原则

素材来源不因换目录而改变。生产中的 32 张攻略图片、四张首页城市发现图片、五张初版素材、选中设计稿和 Logo 母版均保留原路径；与它们字节相同的生成原图在来源清单中链接到这些路径。新恢复的图片与记录共 197 份原文件副本，约 54.2 MiB；另外生成本目录的索引与校验文件。

开发报告复制到可见的 `archive/development/`，便于 GitHub 浏览；已被 Git 跟踪的七份 `.superpowers` 报告保留原位。`.gitattributes` 对 `archive/` 关闭自动换行转换，使日志与原文件字节一致。

历史文档中会出现原作者机器路径、旧提交号、当时的待办或未验证状态。这些内容是历史证据；后续结论应结合 [发布报告](../docs/reports/2026-08-19-xingyu-closed-loop.md)、[Design QA](../design-qa.md) 和 Git 历史阅读。不会将失败日志改标为通过。

原需求中的阿里云、数据库、后台、实名认证等描述属于当时计划。当前已交付应用采用 Vercel 与浏览器本地演示闭环，使用说明见 [ReadMe.md](../ReadMe.md)。第三方网站参考截图保留其参考属性，不作为行屿原创素材重新授予权利。

## 完整性复核

```bash
node scripts/verify-assets-archive.mjs
```

从仓库根目录执行。校验会核对完整文件集合（Git checkout 使用已跟踪文件；GitHub ZIP 使用排除缓存后的文件树）、所有清单条目的哈希、来源映射及图片尺寸。

清单对应此次归档提交，不会自动随未来代码修改更新。检查历史归档时请使用该提交的完整文件树。

缺失项与排除范围详见 [资产总目录](../ASSETS.md)。这是一份现存资产的归档，不宣称能恢复已经清理的临时附件或未找到的早期 DOCX。
