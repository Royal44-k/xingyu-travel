# 行屿国内自由行平台：网站设计与 Vercel 架构规格

- 日期：2026-08-16
- 状态：视觉方向已确认，工程方案待用户审阅
- 视觉目标：[方案 1：山岚画册](../../design/selected-homepage-option-1.png)
- 参考气质：丽思卡尔顿的编辑式奢华与万豪的任务型搜索入口；不复制其品牌资产、文案或版式细节

## 1. 产品结果

建设一个公开可访问、移动端优先且具备桌面沉浸感的国内自由行 Web 平台。首版面向 18–35 岁用户，以“透明比价 → 攻略转行程 → 可信搭子 → AI 行程守护”为闭环。

首个公开版本采用沙箱数据和模拟供应商适配器，完整演示产品主链路，但不伪装成真实出票、预订、支付、实名核验或官方应急服务。所有外部能力通过显式接口隔离，取得供应商、身份核验、天气、航班、地图和百炼密钥后可逐项替换。

工作品牌固定为“行屿 XINGYU”。品牌语为“把远方，变成一段安心抵达的旅程”。

## 2. 交付范围

### 2.1 本轮必须交付

1. 沉浸式首页和全局响应式导航。
2. 机票、酒店、门票三类统一比价体验，展示含税总价、附加条件、更新时间和供应商可信度。
3. 攻略广场、攻略详情以及“一键转为行程草稿”。
4. 行程工作台，可编辑节点、预算和同行决策，并开启守护。
5. 旅游搭子意愿发布、可解释匹配、双向同意和模拟站内聊天。
6. AI 旅行助手，包含常规规划与突发事件 Plan A/B/C 结构化结果；无密钥时使用清晰标注的本地演示引擎。
7. 行程守护风险提醒，覆盖航班延误、恶劣天气和景区关闭的演示事件。
8. 登录、实名与外部预订均使用安全的演示状态，不收集真实身份证、联系方式或付款数据。
9. Vercel 预览和生产部署，提供可公开访问的 `vercel.app` 地址。

### 2.2 本轮不交付

- 真实 OTA 库存、下单、支付、退款或自动改签。
- 真实身份证二要素、人脸识别或短信发送。
- 未成年人互动、国际目的地、原生 App、小程序和短视频。
- 真实 WebSocket 聊天基础设施；公开演示采用本地会话，正式环境预留托管实时服务适配器。
- 未经过法律、通信管理和文旅主管部门评估的商业化上线承诺。

## 3. 工程路径比较

### 路径 A：Vercel 原生产品级 MVP（采用）

使用 Next.js App Router 同时承担页面、轻量 API 和流式 AI 响应；业务规则放入独立 TypeScript 包，外部服务使用适配器。演示数据可直接部署，数据库、对象存储和实时服务按环境启用。

- 优点：最快获得公开地址；预览环境、回滚、图片优化和流式响应天然适配；部署维护面最小。
- 代价：长连接、持续 Worker 和复杂后台任务不能照搬阿里云常驻进程模型，需要托管实时服务、Cron 或 Workflow。

### 路径 B：Next.js + NestJS 双应用 Monorepo

保留原规格中的 NestJS 模块化单体，将 Web 与 API 分开部署。

- 优点：最接近后续大型团队的服务边界；OpenAPI、领域模块和后台任务更传统。
- 代价：在 Vercel 上处理 Nest 冷启动、长任务、SSE 和 WebSocket 的复杂度更高；对首个公开 MVP 的收益不足。

### 路径 C：纯前端高保真演示

只实现视觉与浏览器本地状态，不建设 API 契约。

- 优点：实现最快。
- 代价：无法验证适配器、结构化 AI、状态机和未来数据接入，不符合“后续实际开发基于此”的目标。

路径 A 是当前推荐方案。它保留领域契约和未来拆分空间，同时避免为尚未取得的供应接口提前建设常驻后端。

## 4. 信息架构与主链路

### 4.1 路由

| 路由 | 目的 | 核心完成动作 |
|---|---|---|
| `/` | 品牌首页与统一起点 | 选择产品类型并开始规划 |
| `/compare` | 三类产品统一比价 | 筛选、解释总价、收藏、模拟跳转 |
| `/square` | 攻略广场 | 浏览个性化或时间排序内容 |
| `/square/[slug]` | 攻略详情 | 抽取地点并生成行程草稿 |
| `/trips/[id]` | 行程工作台 | 编辑节点、预算、同行意见和守护状态 |
| `/partners` | 搭子匹配 | 填写意愿、查看解释、发起双向同意 |
| `/chat/[matchId]` | 模拟站内聊天 | 完成安全提示后的会话体验 |
| `/assistant` | AI 旅行助手 | 获取规划回答或结构化应急备选 |
| `/guardian/[tripId]` | 行程守护 | 查看风险事件、证据与 Plan A/B/C |
| `/profile` | 演示账户与偏好 | 管理收藏、推荐开关和隐私状态 |

### 4.2 端到端故事

1. 用户在首页选择“机票”，输入“大理、8 月 22–27 日、2 位”。
2. 比价页分批显示沙箱报价，并解释税费、行李和退改条件。
3. 用户进入攻略广场，打开“大理五日慢游”，生成可编辑行程草稿。
4. 在行程工作台中，用户发布搭子意愿并得到前三项匹配理由。
5. 双向同意后开启模拟聊天；页面始终展示不交换敏感信息的安全提醒。
6. 用户开启行程守护，系统模拟检测到天气风险。
7. AI 助手返回带来源时间、预计成本、耗时、风险等级的 Plan A/B/C，且不自动下单。

## 5. 视觉系统

### 5.1 视觉原则

- 沉浸先于罗列：首屏只承担品牌表达和统一搜索，不堆叠全部功能卡片。
- 编辑感先于 SaaS 感：使用大图、留白、细分割线和清晰排版，避免卡片套卡片。
- 信息可信：报价、AI 和风险提醒使用明确数据标签，不用夸张增长数字或伪实时感。
- 动效服务叙事：滚动、切换和状态变化要帮助用户理解路径，不以炫技干扰搜索。

### 5.2 设计令牌

| 类别 | 令牌 | 值 |
|---|---|---|
| 主墨色 | `--ink` | `#10100F` |
| 暖白 | `--ivory` | `#F4F0E8` |
| 砂金 | `--sand` | `#B79A68` |
| 雾灰 | `--mist` | `#D8D3CA` |
| 深松 | `--pine` | `#26312B` |
| 标题字体 | `--font-display` | `Noto Serif SC` |
| 正文字体 | `--font-ui` | `Noto Sans SC` |
| 内容最大宽度 | `--content-max` | `1320px` |
| 控件圆角 | `--radius-control` | `10px` |
| 大面板圆角 | `--radius-panel` | `18px` |

### 5.3 首页结构

1. 透明叠加导航：左侧品牌，中央五个主要入口，右侧“我的行程”。滚动 48px 后变为暖白实底。
2. 视口级英雄区：真实中国山川影像、品牌标题、两行短文案、细线式目的地路径提示。
3. 一体化搜索台：机票/酒店/门票标签、地点、日期、人数和“开始规划”；键盘可完整操作。
4. 编辑式目的地带：两张精选目的地影像，悬停时遮罩和标题缓慢上移。
5. 真实总价解释：用一条横向报价对比说明“为什么这个价格可比”。
6. 攻略转行程：展示一篇真实感攻略及抽取后的行程摘要。
7. 搭子与安全：呈现匹配理由而非相似度噱头，并突出 18+ 实名边界。
8. 行程守护：展示一次风险事件与三个备选方案入口。
9. 页脚：业务声明、隐私、算法推荐设置、AI 模型公示和演示环境说明。

### 5.4 动效与可访问性

- Hero 使用低幅度视差和图片交叉淡化；移动端关闭大范围视差。
- 目的地路径采用可访问的 DOM 文本与图标组件，不使用手绘 SVG 代替资产。
- 搜索标签以 180–240ms 过渡切换字段；结果页报价以错峰方式进入。
- `prefers-reduced-motion` 下禁用视差、粒子和大位移动画，仅保留淡入淡出。
- 所有交互具备键盘焦点、语义标签和至少 4.5:1 的正文对比度。

## 6. Vercel 目标架构

### 6.1 代码结构

```text
xingyu-travel/
├─ src/app/                 # 页面、布局、Route Handlers
├─ src/features/            # comparison、square、trips、partners、assistant、guardian
├─ src/components/          # 可复用 UI 与品牌组件
├─ src/domain/              # 纯 TypeScript 领域类型、规则和状态机
├─ src/adapters/            # mock、数据库、LLM、天气、航班和实时服务适配器
├─ src/data/                # 可重复的沙箱数据
├─ public/                  # 经许可或生成的静态图像
├─ tests/                   # 单元、组件和端到端测试
└─ docs/                    # 设计、实施和部署说明
```

首轮保持单个 Next.js 应用，不创建没有独立运行价值的工作区包。领域模块必须只依赖契约，页面不得直接读取供应商响应。

### 6.2 运行时映射

| 原阿里云能力 | Vercel 方案 | 首个公开版本 |
|---|---|---|
| ECS + ALB | Next.js 部署与 Vercel Functions | 启用 |
| RDS PostgreSQL | Marketplace PostgreSQL，通过 `DatabaseProvider` 接入 | 使用内存沙箱适配器 |
| OSS + CDN | `public/` 静态资产；用户上传后切换 Vercel Blob | 静态生成资产 |
| Tair Redis | Marketplace Redis 或外部托管 Redis | 不作为演示依赖 |
| 常驻 Worker | Cron Jobs / Workflow / 队列适配器 | 通过可重复的模拟事件触发 |
| WebSocket | 托管实时服务适配器 | 浏览器会话内模拟聊天 |
| SLS / ARMS | Vercel Logs、Analytics 和 Speed Insights | 基础日志与 Web Vitals |
| KMS / 凭据管理 | Vercel 加密环境变量 | 仅定义变量名，不提交密钥 |

### 6.3 API 和适配器

- 所有 API 使用 `/api/v1`，返回 `request_id` 和统一错误结构。
- `POST /api/v1/comparison/searches` 创建搜索，`GET /api/v1/comparison/searches/:id/events` 使用流式响应模拟增量报价。
- AI 路由始终返回 `risk_level`、`answer`、`alternatives`、`evidence`、`data_freshness` 和 `requires_human_help`。
- `InventoryProvider`、`LLMProvider`、`WeatherProvider`、`FlightStatusProvider`、`IdentityProvider` 和 `RealtimeProvider` 均有 mock 与生产接口。
- 缺少外部密钥时返回带 `demo_mode: true` 的安全演示结果，不静默伪造实时事实。

## 7. 交互状态与错误处理

- 搜索：`idle → validating → searching → partial → complete | degraded | failed`。
- 攻略转行程：`extracting → review → accepted | edited | discarded`。
- 搭子匹配：`draft → active → suggested → mutual → chatting → closed`。
- 守护事件：`detected → notified → acknowledged → monitoring → resolved`。
- 外部供应商超时不清空已返回结果，显示供应商级失败和最后更新时间。
- AI 工具失败时保留已验证事实并说明缺失项；高风险问题优先展示 110、120、119 和官方渠道提示。
- 演示模式所有外链预订按钮先显示“即将前往合作方”的确认层，禁止虚构订单成功。

## 8. 验收标准

1. 1440×1024 首页与选定视觉方向在构图、层级、色彩和图像气质上匹配；移动端无横向溢出。
2. 首页搜索、三类比价标签、筛选、收藏、攻略转行程、搭子匹配、聊天、守护和 AI 备选均可完成主路径。
3. 演示与真实能力的边界在界面和 API 中均可识别。
4. 单元和组件测试覆盖价格标准化、匹配评分、AI 结构校验与关键状态机。
5. 浏览器端到端测试覆盖完整故事，控制台无未处理错误。
6. Lighthouse 目标：Performance ≥ 85，Accessibility ≥ 95，Best Practices ≥ 95，SEO ≥ 90；受部署网络和第三方脚本影响时记录差异。
7. 视觉对照报告 `design-qa.md` 的最终结果为 `passed`，所有 P0/P1/P2 项已关闭。
8. Vercel 生产部署状态为 READY，公开 URL 能在未登录窗口访问。

## 9. 安全与产品声明

- 不在演示环境采集身份证、精确位置、健康信息、真实联系方式或支付数据。
- AI 输出标记模型/演示引擎、证据来源和数据时间，不将建议描述为医疗诊断、法律结论或官方救援承诺。
- 18 岁以下用户不可发布搭子意愿、匹配或私聊。
- 推荐页提供“按时间排序”入口与演示偏好清除操作。
- 所有图片使用生成资产或允许使用的来源；不复用丽思卡尔顿、万豪的照片、Logo 和商业文案。

## 10. 发布策略

每次功能分支先生成 Vercel Preview，端到端验收通过后再提升为 Production。数据库迁移在未来启用 PostgreSQL 时采用向前兼容策略；外部供应商、AI 和实名能力全部受特性开关控制。生产地址使用 Vercel 自动域名，绑定自有域名作为后续独立操作。
