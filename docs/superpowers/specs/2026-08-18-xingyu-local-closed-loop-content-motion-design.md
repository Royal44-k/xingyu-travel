## 1. 改造目标

本轮将当前公开演示从“功能页面集合”升级为“浏览器本地可持续使用的旅行工作区”。用户在一个浏览器内产生的兴趣偏好、攻略喜欢、报价收藏、降价提醒、攻略转行程、行程编辑、搭子匹配和守护方案必须形成可找回、可继续、可解释的闭环。

同时扩展国内目的地内容和沉浸式影像，避免产品长期围绕大理、桂林、川西重复展示。视觉继续沿用行屿已确认的东方编辑式高级旅行语言，以“移动的旅行取景窗”为唯一核心视觉签名；动效服务内容发现、状态反馈和旅程推进，不追求无意义炫技。

### 1.1 成功结果

1. 清空兴趣标签后，用户仍能从标签库或自定义输入重新添加并恢复个性化推荐。
2. 灵感广场的喜欢状态刷新后保留，并能在个人中心“喜欢”中查看、取消和进入原攻略。
3. 报价收藏和降价提醒刷新后保留，并能在个人中心集中管理。
4. 攻略确认转为行程后立即出现在“我的行程”，不再跳转到固定 `/trips/demo` 死路。
5. 首页、广场和攻略详情覆盖至少八条完整国内目的地攻略，每篇至少四张独立、统一 3:2 展示比例的图片。
6. 首页与内容页具备轮播、悬浮、滚动显现和选中高光；键盘、触控与 reduced motion 均可正常完成核心任务。
7. 现有比价、搭子、聊天、AI 助手、行程守护和安全边界不发生功能回退。

## 2. 范围与非目标

### 2.1 本轮范围

- 浏览器本地持久化的个人资料、兴趣、喜欢、报价收藏、降价提醒和行程索引。
- 新的 `/trips` 行程集合页和重构后的 `/profile` 个人中心。
- 统一导航、AI 助手入口和数据驱动的“我的行程”“行程守护”入口。
- 灵感广场搜索、目的地/主题/天数筛选、喜欢状态和内容扩展。
- 攻略详情四图轮播、缩略图导航、转行程闭环和沉浸式滚动节奏。
- 首页目的地胶片轮播、精选攻略、比价说明、AI 应急、可信搭子、行程守护与最近行程模块。
- ImageGen 项目素材生产、资产登记、尺寸/清晰度/内容检查和 provenance 记录。
- 单元、组件、E2E、无障碍、响应式、视觉对照和 Vercel Production 验证。

### 2.2 非目标

- 不增加真实账号登录、跨设备云同步、数据库或服务端用户画像。
- 不增加真实后台推送；“降价提醒”明确为当前浏览器的演示设置。
- 不接入真实 OTA 库存、支付、订单、退款或自动改签。
- 不采集身份证、精确位置、健康信息、真实联系方式或支付信息。
- 不在本轮建设 CMS、商家后台、评论后端、真实点赞计数或社交关系图。
- 不使用第三方旅游品牌照片、Logo、网页抓取素材或无法确认授权的图片。

## 3. 方案选择

### 3.1 采用：分域存储与统一个人中心

- `profile-store` 只负责兴趣与推荐偏好。
- 新增 `library-store` 负责喜欢的攻略、收藏报价与降价提醒。
- `trip-store v2` 成为行程唯一正式数据源，并吸收旧草稿。
- `/profile` 通过 selector 聚合各领域数据，不复制领域对象。
- `/trips` 提供行程索引，详情继续使用 `/trips/[slug]`。

该方案保持领域边界清晰，避免把所有用户资产塞入一个巨型 profile store，并允许未来用同一接口把浏览器适配器替换为账号云同步适配器。

### 3.2 未采用方案

1. **扩大现有 profile store**：短期文件更少，但偏好、内容收藏、报价和行程生命周期会互相耦合，迁移与测试成本持续上升。
2. **立即接入账号与数据库**：可以跨设备同步，但会引入认证、隐私、数据删除、后端运维和安全评估，超出已确认的浏览器本地范围。

## 4. 信息架构

| 路由 | 主要职责 | 本轮变化 |
|---|---|---|
| `/` | 品牌首页与统一入口 | 增加目的地轮播、精选攻略、比价解释、AI/搭子/守护和最近行程 |
| `/square` | 内容发现 | 增加搜索、筛选、持久化喜欢和更丰富攻略 |
| `/square/[slug]` | 攻略详情 | 四图轮播、缩略图、喜欢、转行程闭环 |
| `/trips` | 我的行程 | 新增；按状态展示、继续规划、比价、搭子和守护入口 |
| `/trips/[slug]` | 行程工作台 | 接受统一 trip store 数据，不依赖固定演示 slug |
| `/profile` | 个人中心 | 重构为概览、行程、喜欢、收藏报价、搭子安全、兴趣偏好 |
| `/compare` | 统一比价 | 收藏报价和降价提醒接入 library store |
| `/assistant` | AI 旅行助手 | 进入全局导航，并从行程上下文进入 |
| `/partners` | 搭子匹配 | 在个人中心显示摘要与继续入口 |

### 4.1 全局导航

- 桌面一级导航保留：首页、真实比价、灵感广场、寻找搭子、旅行助手。
- 右侧提供“我的行程”和个人中心入口；个人中心使用现有 Phosphor 图标，不新增手绘 SVG。
- “行程守护”作为行程上下文动作存在：有守护行程时进入最近守护行程；没有时进入 `/trips` 并解释如何开启。
- 移动端菜单包含全部一级入口，并在打开/关闭两种状态验证横向溢出、焦点顺序和 Escape。

## 5. 领域模型与持久化

### 5.1 ProfileStore v2

```ts
interface ProfilePreferences {
  personalizedFeed: boolean;
  interestTags: string[];
}

interface ProfileActions {
  addInterestTag(tag: string): void;
  removeInterestTag(tag: string): void;
  replaceInterestTags(tags: string[]): void;
  clearInterestTags(): void;
  resetProfilePreferences(): void;
}
```

- 存储键升级为版本 2，迁移版本 1 的 `personalizedFeed` 与 `interestTags`。
- 标签标准化：去除首尾空格、连续空白折叠、忽略 `#` 前缀、按大小写不敏感去重。
- 单个标签 2–12 个中文/英文可见字符，最多 12 个标签。
- 清空标签时关闭个性化推荐；重新添加首个标签后不自动开启，界面明确提供开启动作。
- 畸形持久化数据继续 fail closed：个性化关闭、兴趣为空、保留原始存储，只有用户点击重置才覆盖。

### 5.2 LibraryStore v1

```ts
interface FavoriteOfferSnapshot {
  key: string;
  provider: string;
  productKind: 'flight' | 'hotel' | 'ticket';
  destination: string;
  totalPrice: number;
  currency: 'CNY';
  policySummary: string;
  observedAt: string;
  expiresAt: string;
  deepLink?: string;
}

interface PriceAlert {
  offerKey: string;
  enabled: boolean;
  createdAt: string;
}

interface LibraryState {
  likedPostSlugs: string[];
  favoriteOffers: Record<string, FavoriteOfferSnapshot>;
  priceAlerts: Record<string, PriceAlert>;
}
```

- 报价键必须复用现有 collision-safe `offerIdentity`，不得用字符串拼接生成新身份。
- 收藏保存标准化快照，不保存供应商原始响应，不把过期价格显示为实时价格。
- 个人中心展示 `observedAt`、`expiresAt` 和“重新比价”，过期项保留但明确标记。
- 本地提醒不暗示后台监听或系统通知；文案固定为“已保存提醒设置；本演示不会在关闭页面后推送”。
- 已移除的攻略 slug 在渲染时显示“内容已不可用”并提供移除动作，不造成页面崩溃。

### 5.3 TripStore v2

- 正式行程、伙伴意愿标记和守护方案继续存放于 `xingyu-demo-v1`，schema 升级为 v2。
- 旧 `xingyu-demo-trip-drafts` 仅作为一次性迁移来源；迁移成功后不自动删除原始数据。
- `savePostAsTrip(post)` 必须在一次动作内创建或返回 canonical trip，保证幂等。
- `sourcePostSlug` 唯一；重复点击“转为行程”进入已有行程并提示“已在我的行程中”。
- map key 始终等于 `trip.id`；slug 只用于解析，所有写路径使用 canonical ID。
- `/trips` 仅从正式 trip store 读取并按 `updatedAt` 降序显示。
- 行程增加 `createdAt`、`updatedAt` 和可选 `coverImage`，迁移时使用稳定默认值。

### 5.4 Hydration 协议

1. 每个 store 使用 `skipHydration`。
2. 页面在 hydrate 完成前只显示中性加载状态，不展示可被迟到数据覆盖的交互。
3. 多 store 页面使用组合 readiness，不允许某一 store 未完成时提交跨域操作。
4. 解析错误不写回；UI 展示明确错误、保留原始数据并提供显式重置。
5. 测试必须覆盖延迟 hydrate、畸形 JSON、合法旧版本、重复迁移与用户操作竞态。

## 6. 核心交互设计

### 6.1 兴趣标签管理

- 标签库分为：旅行方式、自然景观、城市人文、住宿偏好、美食体验、安全与同行。
- 首批标签包含：慢旅行、自驾、海岛、山水、雪山、古镇、城市漫游、人文历史、摄影、美食、亲子、独自出发、周末、轻徒步、雨天出行、安全。
- 预设标签使用可多选 chip；选中态显示勾选与砂金描边，不能只靠颜色表达。
- 支持自定义标签输入，Enter/按钮均可添加；错误在输入附近说明原因。
- “清除全部”需要二次确认；清空后标签库仍保持可见。

### 6.2 攻略喜欢

- 广场卡片和详情页共享同一个 `likedPostSlugs` 状态。
- 点击后立即切换 `aria-pressed`、朱砂心形、一次回弹和暖色边缘高光，并显示非阻塞状态提示。
- 再次点击取消；个人中心和原页面同步。
- 个人中心“喜欢”卡片提供进入攻略与取消喜欢，空状态引导前往灵感广场。

### 6.3 报价收藏与提醒

- 报价行的收藏写入快照；刷新和跨页面后保留。
- 降价提醒依附于收藏报价；取消收藏时提醒同时关闭，并在操作前说明影响。
- 个人中心支持按机票、酒店、门票筛选，提供重新比价和外部跳转确认。

### 6.4 攻略转行程

1. 用户点击“转为行程”。
2. 抽取结果在可访问 drawer 中复核，包含目的地、天数、预算和全部节点。
3. 点击“确认并保存到我的行程”后调用幂等 `savePostAsTrip`。
4. 成功状态提供“查看行程”和“继续浏览”；行程已出现在 `/trips`。
5. 进入工作台后可编辑、比价、发布搭子意愿和开启守护。

### 6.5 我的行程

- 顶部提供数量摘要：规划中、守护中、已归档。
- 每张行程显示封面、目的地、日期、人数、预算、来源攻略和最后更新时间。
- 主动作依据状态变化：继续规划、查看守护、查看归档。
- 次级动作：进入比价、寻找搭子、开启/关闭守护。
- 空状态提供“从攻略创建”和“直接开始比价”，不跳入不存在的演示 slug。

### 6.6 个人中心

- 概览：本地演示身份、安全边界、最近行程、喜欢/收藏数量和继续操作。
- 我的行程：复用行程 selector 和卡片，不复制 trip 数据。
- 喜欢：攻略卡片集合。
- 收藏报价：报价快照、有效期和提醒状态。
- 搭子与安全：当前意愿、可见匹配、可信联系人/签到状态摘要，只链接到领域页面。
- 兴趣偏好：完整标签管理和推荐开关。
- URL query `?tab=` 支持可分享的面板状态；非法 tab 回到概览。

### 7.2 图片规范

- 八篇完整攻略每篇至少四张独立场景图片，共至少 32 张详情资产。
- 新资产使用内置 ImageGen，分类为 `photorealistic-natural`；每个场景单独生成，不使用拼贴后裁切或 sprite sheet。
- 目标源尺寸统一为 1536×1024、3:2 横图；UI 显示使用固定 3:2 容器与 `object-fit: cover`。
- 画面使用自然光、真实材质和低饱和电影感；避免过度 HDR、夸张天空、假地图、文字、Logo、水印和可识别人脸。
- 每张图片必须检查：地域特征、主题正确、清晰度、重复内容、文字/水印、脸部、构图安全区和裁切。
- 资产登记包含文件名、尺寸、alt、目的地、场景、生成方式、最终提示词和限制条件。
- 生成资产复制到 `public/assets/destinations/<destination>/`，不得只留在 `$CODEX_HOME/generated_images`。
- 生产构建使用 Next Image；首屏优先图设置 priority，其余懒加载并提供稳定尺寸，避免布局抖动。

## 8. 视觉系统与动效

### 8.1 视觉签名

“移动的旅行取景窗”表现为横向目的地画幅、当前地点放大、相邻城市露出、地点/季节/天数沿轨道切换。该装置用于首页和广场头部，不复制到每个模块；其余界面保持克制。

### 8.2 颜色与字体

| 角色 | 值 | 用途 |
|---|---|---|
| 墨黑 `--ink` | `#10100F` | 深色画布与正文 |
| 宣纸白 `--ivory` | `#F4F0E8` | 明亮页面与反白文字 |
| 指南针金 `--sand` | `#B79A68` | 重点、焦点、轨道和选择描边 |
| 松针绿 `--pine` | `#26312B` | 主按钮与可信状态 |
| 湖水青 `--lake-jade` | `#4D6B63` | 守护、信息和低饱和辅助状态 |
| 朱砂红 `--cinnabar` | `#A94032` | 喜欢与谨慎使用的警示强调 |

- 大标题继续使用 Noto Serif SC 400/500；正文与控件使用 Noto Sans SC。
- 数据与时间使用 Noto Sans SC、tabular numerals 和克制字距。
- 不增加新的远程字体依赖。

### 8.3 首页结构

```text
[全屏品牌 Hero + 统一搜索]
[移动旅行取景窗：目的地胶片轮播]
[精选攻略：海岛 / 城市 / 山野 / 人文]
[真实总价解释 + 收藏报价入口]
[攻略转行程闭环示例]
[AI 应急助手 + 行程守护场景]
[可信搭子与安全边界]
[最近行程 / 喜欢内容（本地有数据时）]
[合规与演示说明页脚]
```

### 8.4 动效令牌与行为

- `--motion-fast: 160ms`：心形、按钮、chip、焦点状态。
- `--motion-standard: 320ms`：卡片悬浮、tab、drawer 和轮播控制。
- `--motion-reveal: 620ms`：分区滚动显现和低幅度景深。
- 标准 easing：`cubic-bezier(.22, .61, .36, 1)`；回弹只用于收藏成功一次。
- 轮播 6 秒自动前进，支持拖拽、箭头、分页、Home/End 和左右方向键；hover、focus、触控拖拽、页面不可见时暂停。
- 悬浮位移不超过 8px，图片缩放不超过 1.035；高光仅用于 selected/hovered/focused，不铺满页面。
- 滚动显现只执行一次；首屏重要内容不依赖滚动才能可见。
- `prefers-reduced-motion` 下停止自动播放、视差、回弹和大位移，直接展示稳定最终状态。

## 9. 组件边界

- `InterestTagPicker`：标签标准化、选择 UI 与错误提示；不负责持久化。
- `DestinationFilmCarousel`：轮播状态、暂停规则、键盘和 reduced motion。
- `GuideGallery`：四图 3:2 画廊、缩略图、触控和键盘。
- `FavoriteButton`：共享喜欢动作、ARIA 与微动效，不自行保存状态。
- `OfferFavoriteButton` / `PriceAlertToggle`：只调用 library actions。
- `TripCard` / `TripCollection`：接收 selector 结果，不直接读 localStorage。
- `ProfileHub`：负责 tab 路由与聚合布局，不拥有领域数据。
- `HydrationBoundary`：组合 store readiness、错误与安全恢复动作。

任何组件不得直接调用 `localStorage`；持久化只通过 store adapter 完成。

## 10. 错误、空状态与安全边界

- 兴趣为空：显示标签库与“选择兴趣”，不只显示不可恢复说明。
- 喜欢为空：说明“喜欢的攻略会保存在这里”，提供进入广场按钮。
- 行程为空：提供从攻略创建和开始比价两个明确动作。
- 报价过期：保留快照，显示“报价可能已变化”和重新搜索。
- 内容下架：保留收藏记录的不可用状态，允许用户移除。
- 图片失败：保持同尺寸中性品牌背景、alt 与重试；不得用另一景点图片冒充。
- store 校验失败：只使用 fail-closed 内存状态，原始数据不覆盖，提供显式重置。
- 外部预订仍需确认层；本地收藏、提醒和行程不描述为真实订单或后台服务。
- AI、搭子和守护继续显示沙箱、数据时间、风险边界和官方紧急服务优先级。

## 11. 测试与验收

### 11.1 单元测试

- 兴趣标签标准化、重复、数量/长度边界、清空与恢复。
- library 喜欢切换、collision-safe 报价键、过期快照和提醒依赖。
- trip v1→v2、旧 draft 导入、幂等保存和 canonical key 不变量。
- 所有 store 的畸形数据 fail closed、原始数据不覆盖和显式重置。
- 内容数据保证八篇完整攻略、每篇至少四图、路线天数与 itinerary 一致。

### 11.2 组件测试

- 标签库清空后仍可选，自定义标签可添加/删除，推荐开关规则正确。
- 广场/详情/个人中心喜欢状态同步并持久化。
- 报价收藏和提醒同步到个人中心，取消收藏处理提醒。
- 轮播自动暂停、箭头、分页、方向键、Home/End、触控和 reduced motion。
- 转行程确认后列表立即出现，重复转换进入已有行程。
- loading、empty、expired、missing 和 hydration error 状态。

### 11.3 E2E 主链路

1. 兴趣清空 → 重新选择“海岛/城市漫游” → 开启推荐 → 刷新仍保留。
2. 广场喜欢三亚攻略 → 刷新 → 个人中心喜欢 → 进入原攻略 → 取消喜欢。
3. 攻略转行程 → `/trips` 出现新行程 → 继续编辑 → 进入比价。
4. 收藏一条报价并开启提醒 → 个人中心查看 → 重新比价 → 取消收藏。
5. 行程发布搭子意愿 → 匹配聊天 → 开启守护 → 选择 Plan A。
6. 桌面与移动端轮播、导航、gallery、dialog 和 tab 全键盘操作。

### 11.4 Design QA

- 参考源：既有首页目标、扩展视觉目标板和本规格中的准确 token/文案。
- 实现证据：1440×1024 桌面、390×844 移动，以及 hover/focus/selected/empty/error 状态截图。
- 把参考与实现放入同一对照图，检查字体、布局节奏、颜色、图片质量和产品文案。
- 每个 P0/P1/P2 必须经历 blocked → 修复 → 同视口复拍 → 复核；最终 `design-qa.md` 为 `passed`。
- 浏览器使用已获用户允许的本机 Chrome；检查 console、page error、HTTP ≥400、Axe critical/serious 和横向溢出。

### 11.5 工程与性能门槛

- `pnpm lint`、`pnpm typecheck`、全量 Vitest、`pnpm test:e2e` 和 `pnpm build` 全部通过。
- 首页首屏不一次下载全部详情图；轮播只优先当前图和邻近图。
- 移动网络下图片保持稳定比例，不出现大范围 CLS。
- 动效不创建持续高 CPU 的全局 RAF；不可见页面暂停自动轮播。
- Lighthouse 目标延续：Performance ≥85、Accessibility ≥95、Best Practices ≥95、SEO ≥90；差异必须记录。

## 15. 自审结论

- 本规格没有占位内容或依赖未决定的交互。
- 浏览器本地闭环与“未来云同步适配层”不矛盾：本轮不建设后端，但 store/action 边界可替换。
- 视觉目标板只定义可见方向，准确文本和交互由本规格约束，避免生成图文字误差进入产品。
- 内容扩展、状态修复和动效优化均服务当前用户目标，没有引入站内支付、真实实名或其他无关范围。
- 实施范围可以拆分为顺序明确的任务，但属于一个可验证的闭环版本，无需再拆成独立产品项目。
